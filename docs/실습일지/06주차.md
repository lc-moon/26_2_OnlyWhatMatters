### 2. OSV 취약점 데이터 사전 검증
- 목적: LLM이 취약 함수를 뽑으려면 근거 문서(수정 커밋 diff, 설명문)가 필요함. PyPI 취약점 중 근거가 붙은 비율을 실측
- 결과를 보고 기준을 맞추지 않도록 **판정 기준을 측정 전에 먼저 정함**
  - 최근 2년 취약점 중 분석 가능 후보 50% 이상 → 계획대로 / 25~50% → 계획 유지 / 25% 미만 → 범위 조정
- 덤프 표본 확인 결과 악성 패키지(MAL) 11,812건(45%), 철회 항목 595건이 섞여 있어 분리
- 같은 취약점이 여러 ID(PYSEC·GHSA·CVE)로 중복 → aliases로 묶어 고유 취약점 6,718건(최근 2년 3,278건)
- 취약 함수를 구조화 필드에 넣은 항목은 26,126건 중 **2건뿐** → 함수 정보는 설명문 줄글에만 있음. LLM 사용 전제 확인
- 신규 취약점 월평균 133.2건(일 4.4건), 2026년 4~9월은 월평균 298.8건(일 약 9.8건)으로 증가
- 실행 결과 → [캡처 2: OSV PyPI 사전 검증 요약 표]
- 소스코드 — 수정 커밋 출처별 추출 (`scripts/analyze_osv.py:113-127`)
  ```python
  fix_refs = [x["url"] for x in rec.get("references", []) if x.get("type") == "FIX"]
  # 실제 데이터에서는 수정 커밋이 WEB 등 다른 타입으로 붙는다(GHSA는 전부 WEB).
  # 측정 전 기준에는 없던 출처라 따로 세고, 근거로 인정하는 것은 D-003 결정에 따른다
  other_gh_commits = [gh_commit_url(*GH_COMMIT_RE.match(x["url"]).groups())
                      for x in rec.get("references", [])
                      if x.get("type") != "FIX" and GH_COMMIT_RE.match(x["url"])]
  fix_gh_commits, fix_gh_pr, fix_other = [], 0, 0
  for url in fix_refs:
      m = GH_COMMIT_RE.match(url)
      if m:
          fix_gh_commits.append(gh_commit_url(*m.groups()))
      elif GH_PR_RE.match(url):
          fix_gh_pr += 1
      else:
          fix_other += 1
  ```
- 소스코드 — 악성·철회 항목 분리 후 중복 ID 묶기 (`scripts/analyze_osv.py:199-215`)
  ```python
  for rec in iter_records(zf):
      prefix[rec["id"].split("-")[0]] += 1
      if "withdrawn" in rec:
          withdrawn += 1      # 철회된 항목은 분석에서 뺀다
      elif rec["id"].startswith("MAL-"):
          mal += 1            # 악성 패키지는 "취약 함수"가 없는 다른 종류의 데이터다
      else:
          entries.append(extract(rec))

  uf = UnionFind()
  for e in entries:
      uf.find(e["id"])
      for a in e["aliases"]:
          uf.union(e["id"], a)
  groups = {}
  for e in entries:
      groups.setdefault(uf.find(e["id"]), []).append(e)
  ```

### 3. 수정 커밋 근거 범위 변경 (FIX 링크 → WEB 타입 커밋 포함)
- 기존 방식: LLM 입력이 될 수정 커밋을 OSV의 `FIX` 타입 링크와 GIT range의 `fixed` 커밋에서만 가져오기로 함
- 문제: 이 기준으로 최근 2년 분석 가능 후보가 **10.8%**에 그쳐 사전 기준상 "범위 조정"에 해당.
  원인을 추적한 결과 GitHub 보안 권고(GHSA)는 수정 커밋 링크 5,261개를 전부 `WEB` 타입으로 붙이고, `FIX` 타입은 PyPI 권고(PYSEC)만 사용함
- 검증: FIX 커밋과 WEB 커밋이 함께 있는 1,241건을 대조한 결과 **99.8%에서 WEB 커밋이 실제 수정 커밋과 일치**(전부 일치 93.0%)
- 변경과 이유: WEB 타입은 수정 커밋이 아니라는 뜻이 아니라 GHSA의 표기 방식이므로 근거로 인정하도록 변경 → 분석 가능 후보 **53.3%**.
  측정 전 기준은 바꾸지 않고, 기준에 따른 "범위 조정"의 내용으로 근거 출처를 넓힘. 근거가 없는 나머지는 "판단 불가 + 업데이트 권장"으로 처리
- 실행 결과 → [캡처 3: WEB 커밋과 수정 커밋 대조 결과]
- 소스코드 — 대조 로직 (`scripts/analyze_osv.py:418-425`)
  ```python
  both = any_match = all_match = 0
  for v in vulns:
      fix = {key(u) for m in v["members"] for u in m["fix_gh_commits"] + m["git_gh_commits"]}
      web = {key(u) for m in v["members"] for u in m["other_gh_commits"]}
      if fix and web:
          both += 1
          any_match += bool(web & fix)
          all_match += web <= fix
  ```
