## 3. 미확인 리스크

확인되면 결과를 §2로 옮기고 여기서는 체크한다.

- [x] **OSV PyPI 항목 중 FIX 커밋 링크 비율** → §2-5. 기준상 "범위 조정"이었고, 조정 내용은 D-003
  - **판정 기준 (2026-10-08, 측정 전에 정함)** — 기록용으로 남긴다
    - 대상: 최근 2년(2024-10-08 이후) 공개된 고유 취약점(aliases로 묶음). withdrawn·MAL 제외
    - 분석 가능 후보 = GitHub 커밋 diff를 얻을 수 있음(FIX 링크 또는 GIT range) + details 200자 이상
    - 후보 비율 **50% 이상 → 계획대로** / **25~50% → 계획 유지 + 판단 불가 비율을 평가에서 따로 보고** /
      **25% 미만 → 범위 조정**(decisions 항목 추가)
    - 보정: diff 실수신 표본 10건 중 성공이 8건 미만이면 후보 비율 × 성공률로 판정
    - 추가(덤프 표본 확인 후·집계 전): FIX가 아닌 타입(WEB 등)으로 붙은 GitHub 커밋 URL은 **참고 행으로만** 표시하고
      판정에는 넣지 않는다. 수정 커밋이 아닐 수 있기 때문. 두 기준에서 판정이 갈리면 decisions에 남긴다
    - 경계값 50%·25%는 데이터가 아니라 판단이다. 25% 미만이면 경고 넷 중 셋 이상이 Dependabot 수준으로
      떨어져 차별점(D-001)이 소수에만 적용되고, 과반이면 "알림 피로를 줄인다"는 주장이 성립한다고 봤다
- [x] **OSV PyPI에 취약 함수가 구조화된 필드로 있는가** → §2-8. 사실상 없다
- [x] **Python 생태계의 신규 취약점 발생량** → §2-10. 일 4~10건. 이 건수로 실제 비용이 얼마인지는 9주차 호출 단가 실측 후
- [ ] **WEB 커밋만 있는 취약점에서도 그 커밋이 수정 커밋인가** — §2-6의 일치율은 PYSEC가 FIX를 달아준 묶음에서 잰 것이다.
  7주차 정답 작성 때 후보 중 WEB 출처 18건을 확인한다(D-003)
- [ ] **신규 취약점 증가 추세** — 2026년 들어 월 100건대에서 300건 안팎으로 늘었다. 계속 늘면 D-002의 비용 전제를 다시 본다
- [ ] **requirements.txt는 직접 의존성만 담는다** — 간접 의존성이 빠진다. lock 파일 우선 지원으로 대응 예정
- [ ] **ast 분석의 예외 케이스** — 별칭 import, 클래스 메서드, 함수를 변수에 담는 경우 등.
  완벽 대신 "판단 불가" 비율을 관리한다
